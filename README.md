# SVG PathTwicker
Inkscape is a great tool to draw SVG elements.  In an application where many elements from many files come together and may be manipulated in a greater map, 
stems the requirement recalculate "d" attribute, from which, a reference point may be used to plot and tranform on a map.

## Context
This SVG Path Tweaker read from SVG files created using Inkscape, extracts 'd' attribute found in path elements, and process to a new CSV file where a few key data relative to the drawing are extracted and simplified for easier human reading. 'rect', 'circle', 'ellipse', 'polyline', 'polygon' and 'line' elements are also read, and converted to their equivalent path 'd' data before going through the same process.

## Attribute 'd' reading instructions
For each element with tag path, the d attribute shall read like the pen move relative to start point with is always 'm' (i.e: 0,0).  A transform instruction will move the element to correct position on the map in reading application, hence translation vector is collected separatly.
The transform of the element itself (attribute, or CSS property in style) may be a list of translate, scale, rotate, skewX, skewY and matrix. The transforms of the parent groups (g) are merged with it, the element's own being applied first, then its parent's, and so on outwards.
Of that merged transform, the translation and the rotation angle are kept apart (position of the reference point, i.e. the first move of the path, and the angle the element is turned by around it, default 0), while the rest (scale, skew, flip) is applied to the drawing. The drawing itself thus stays un-rotated.
All subsequent pen move shall convert to relative move instruction, in respect to SVG path element 'd' attribute definition.
Wherever possible, preference should be given to 'c', 'h', 'v' or 'a', use 'l' whence it cannot simplify, and every path shall close using 'z' instruction.
Unit provided in original path is centimeter (100 is one meter). Inkscape creates floating numbers, while in the context anything lower than the unit is meaningless.  Each pen move coordinates shall simplify to integer.
From origin to close, the boxing rectangle holds the whole drawing (the real extent of its curves and arcs, not only the pen position where each move ends), relative to path element, and will open the way for many useful feature, hence it is stored separately while processing.
That rectangle is the smallest one, of any orientation, around the drawing: when it is tilted, its angle is added to the rotation, and the drawing is turned back so that it sits upright in its box (only if this shrinks the box by more than 1%, and by at least half a degree, so a circle or an upright drawing is left alone). Turning is around the reference point, so its position does not move.
That reference point, the origin 0,0 of the drawing, is the top-left corner of the box: the box thus starts at 0,0, Delta X and Delta Y are the map position of that corner, and the rotation turns the drawing around it. The first move of the path is then its offset from that corner (m 0,0 only when the drawing starts on the corner itself).
Optimised path drawing coordinate are relative, and coded so.
Basic shapes (rect, circle, ellipse, polygon, polyline) are calculated into corresponding path element.  
A line has no area of its own, so it becomes the rectangle its stroke covers: the pen 'stroke-width' (from style, else attribute, else 1) is its second dimension.  
Hence this process output produce a list of path element simplified to relative drawing.

## Export CSV
Having the following table structure :
* Layer: file name extracted from source file
* Category: prefix of the path element's id, before the underscore, if any
* Name: path element name, taken from the remainder of its id, if the element is not named, then autogenerated
* Row: sequential row number across the whole export
* original path, unmodified for record and backward engineering (for a converted shape element, this is the synthesized equivalent path, since it has no 'd' attribute of its own)
* Delta X and Delta Y position, used in 'transform' translation parameter
* Rotation, the angle in degrees (default 0) the element is turned by, from the 'transform' of the element and of its parent groups
* Label X and Label Y, the boxing rectangle's center point
* Boxing rectangle x relative to path, y relative to path, width, height
* optimized path resulting from the output path
* CSS class and CSS style, copied from the path element when present
